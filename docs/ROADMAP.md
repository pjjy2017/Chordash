## 1.2 패치
고칠 점을 모았다가 한 번에 진행. (구현 완료 — 사용자 확인 대기)
- **완료 기준:** 처음 켜면 예제 곡이 열리고, 웹에서 다운로드 없이 보관함에 저장·열기·백업이 되며, 휴대폰에서 코드 키보드로 입력되고, ezPDF로 인쇄해도 마침줄·도돌이표가 나오고, 칸 단위로 바로 악보 모양이 된다.
- [x] 1. **첫 사용자용 예제 곡 "Chordash":** 저작권 걱정 없는 직접 만든 곡으로, 주요 입력법(머리말·섹션·키 변경·반복·엔딩·N.C.·악센트·브레스·파트·가사 `_`·위쪽 글자 `^`·색 메모·도수)을 한 곡에 담음. 처음 켜거나 빈 문서일 때 열 수 있게(메뉴 "예제 열기"). `샴푸의요정.chord`를 이 예제로 바꾸고, 테스트·AI 프롬프트 예시도 교체.
- [x] 2. **웹 "내 곡 보관함"(브라우저 저장):** 웹 버전이 곡을 그 브라우저 안(IndexedDB)에 저장 — 열기는 보관함 목록, 저장은 다운로드 없이 바로. 백업 파일로 내보내기·가져오기. 그 기기·브라우저에만 있다는 안내 포함. (사용자 결정: 클라우드는 A안만, 구글 드라이브·자체 계정은 보류)
- [x] 3. **휴대폰 전용 코드 키보드:** 휴대폰(안드로이드 앱·휴대폰 웹)에서 입력 칸을 누르면 일반 키보드 대신 코드 키보드(C~B, b # - ^ 7 9 /, % o + s 6 11 13, 큰 `, 마디` 키, `.` `_` `^` Enter). "가/123" 키로 일반 키보드 전환, 제목 칸·`_` 가사 줄에서는 자동으로 일반 키보드. 맨 위 추천 줄(곡 키에 어울리는 코드). 구현은 입력 칸에 `inputmode="none"` + 앱이 그린 키보드.
- [x] 4. **(버그) 인쇄하면 마침줄·도돌이표 마디선이 안 나옴 — 웹·안드로이드·데스크톱 모두:** 원인 — 마디선을 배경(색·그라데이션)으로 그리는데, 브라우저·안드로이드 인쇄는 "배경 그래픽"이 꺼져 있으면 배경을 빼고 찍음(특히 그라데이션으로 그린 마침줄·도돌이표). 데스크톱 PDF 파일 자체에는 선이 들어 있지만(pdf.js로 확인), 마침줄·도돌이표를 그라데이션(PDF 안에서는 "셰이딩")으로 그려서 PDF 뷰어·프린터에 따라 빠지거나 흐려짐. 고칠 방법: 모든 마디선·도돌이 점을 그라데이션 없이 단색 막대(요소)로 그리고, 악보에 `print-color-adjust: exact`(배경도 그대로 인쇄)를 넣음. 인쇄 화면 확인 추가.
- [x] 5. **악보 모양 변환을 다시 칸 단위(실시간)로:** 1.1의 "줄 단위 변환"은 고칠 코드를 찾아가기 어려움(줄 전체가 글자로 바뀌며 위치가 출렁임). 커서가 닿은 칸만 글자로 돌아가고, 쉼표로 칸을 닫으면 바로 악보 모양(Phase 4.5 방식)으로 되돌림. 코드 풀이는 그 칸에. (Phase 13 결정 되돌림 → DECISIONS 기록)
