## 2026-10-03 (기획 단계, 채팅에서 결정)
- **입력 방식:** 텍스트 입력 + 실시간 미리보기. 클릭 편집은 나중에. — 개발량이 적고 입력이 가장 빠름.
- **스택:** Electron + TypeScript. — 미리보기 HTML을 그대로 `printToPDF` 하면 화면과 PDF가 일치. Flutter/WPF는 화면용·PDF용 레이아웃을 따로 짜야 함. 설치 용량(약 100MB)은 개인용이라 감수.
- **개발 방식:** Claude Code. 기획·문법 결정은 채팅, 구현은 Claude Code.
- **테마:** 테마 전환 지원. 기본값은 손글씨풍·리얼북풍이 아닌 가독성 좋은 굵은 고딕. 확장음 표기(위첨자/한 줄)는 테마마다.
- **레이아웃:** 줄마다 마디 수 자유, 한 줄 안 마디 폭 균등.
- **페이지 넘김:** 자동 + 수동(`---`).
- **파일:** 곡당 텍스트 파일 하나. 앱 내 라이브러리 없음.
- **v1 필수:** 조옮김(전체/섹션), 주석(별표·브레스·색 메모), 반복기호·엔딩.
- **셋리스트 PDF:** 나중에.
- **도수 기본 성질:** 숫자만 쓰면 항상 메이저 (`2` = 메이저, `2-` = 마이너).
- **변환 방식:** 원본 텍스트 그대로 저장, 변환은 미리보기·힌트로만. — 도수 입력 시 키 한 줄로 조옮김 가능.
- **`b` 충돌:** 토큰 맨 앞 소문자 `b` + 숫자 = 플랫 도수. B 코드는 대문자.
- **임포트 추가:** 텍스트 임포트(규칙 기반, 오프라인)와 이미지·PDF 임포트를 v1.x로.
- **이미지 인식 방식:** Claude API 비전. — 전통 OCR(Tesseract 등)은 손글씨와 코드 기호(♭, △, 위첨자, 슬래시)에 약하고, 결과를 우리 문법으로 구조화하는 일도 별도로 필요. 비전 모델은 문법 명세를 받아 바로 chordpad 텍스트로 출력 가능. 대가: 인터넷 필요, API 키와 사용 요금.
- **임포트 결과:** 자동 저장 없음. 새 탭에서 검토 후 사용자가 저장. 불확실한 부분은 `?` 표시.

## 2026-10-04 (Phase 1)
사용자 결정:
- **정규형 임시표:** 루트·베이스·변형 모두 ♯ ♭로 통일 (`C♯mM7`, `A7/C♯`, `E7♯9`). SYNTAX 7장 결과 열 수정. — 기존 표는 `#`와 `♯`가 섞여 있었음.
- **sus 위치:** `cs7` = `c7s` = `C7sus4` → C7sus4.
- **줄 끝 `?`:** 마디 줄 마지막 마디선 뒤 `?` = 줄 전체 확인 필요. — PRD 텍스트 임포트의 "줄 끝 ? 경고"와 맞춤.
- **추가 표기 허용:** `CM7`(=maj7), `Csus`(=sus4), `C69`(→ C6/9), `Cø`(=m7♭5).

구현 중 해석(화성 판단 아님, 문법 문서에서 바로 따라 나오는 것):
- `-`=`m`, `^`=`maj`이므로 `-^`, `mM`, `m^`, `-maj`, `mmaj`를 모두 mM7로 받음.
- 절대루트 뒤 `b`/`#`는 항상 루트 임시표(문법의 `절대루트 = [A-Ga-g][#b]?`): `cb9` → C♭9. 7 없는 ♭9는 `c(b9)` → **C(♭9)** 로, 숫자 없이 붙는 변형은 괄호로 표시해 C♭9와 구분.
- `C6/9`는 슬래시 베이스로 읽히므로 오류로 두고 "69로 입력" 안내 메시지를 줌.
- 마디선 `||`(콜론 없음)는 오류. 마지막 `|`가 빠진 줄(`| C | D`)은 허용.
- 경고(빨간 오류가 아닌 것): 가사 큐 위에 마디 줄이 없음, 한 줄에 가사 큐 두 개, 색 메모 아래에 마디 줄이 없음, `title:` 두 번.
- `title:`/`key:` 줄은 파일 맨 위(첫 섹션·마디 줄 전)에만. 중간 키 변경은 섹션 라벨로만.
- **테스트 방식:** 테스트가 `docs/SYNTAX.md`의 7장 표를 직접 읽어 행마다 테스트를 만듦. — 표와 테스트가 어긋날 수 없음(CLAUDE.md 규칙 3). 표별 행 수도 확인해 표 형식이 깨지면 실패.
- **7.5 조옮김 표:** Phase 5 범위라 "할 일(todo)" 테스트로만 등록.
- **문서 모델:** `parse(text)` → `{ document, diagnostics }`. 예외를 던지지 않고 오류를 줄·칸 위치와 함께 돌려줌(Phase 3 에디터 밑줄용). 코드마다 입력 원문, 해석 구조(도수 그대로), 철자된 결과를 함께 보관(Phase 5 조옮김용).

## 2026-10-04 (Phase 2)
사용자 결정:
- **추가 표기:** `cs4`(=sus4), `alt`(알터드 도미넌트) 허용. 숫자 없는 `Calt`는 C7alt로 봄(내 해석, SYNTAX 4.3 기록).
- **마이너 표시(굵은 고딕):** `−` (C−7). 정규형(`Cm7`)은 그대로이고 화면 표시만 바뀜. 하이픈(-) 대신 폭이 넓은 수학 마이너스(−, U+2212)를 씀 — 굵은 글씨에서 하이픈이 너무 짧아 보임.
- **짧은 줄:** 마디 폭은 한 줄 4마디 기준. 4마디보다 적으면 왼쪽부터 채우고, 5마디 이상이면 줄 폭에 맞게 좁힘.
- **섹션 이름:** 섹션 첫 줄 위에 굵게.
- **가사 큐:** 마디 줄 바로 아래 작은 회색 글씨.

구현:
- **굵은 고딕 표시 규칙:** 루트 + (−, °, + 는 줄 위에) + 나머지(확장음·△·ø·sus·변형·alt)는 위첨자. maj7 → △7, m7♭5 → ø7, mM7 → −△7, dim7 → °7, aug7 → +7. 플레인 테마용 옵션(maj/m7♭5/dim, 한 줄 표기)도 함수에는 들어 있으나 테마 전환은 Phase 4.
- **레이아웃은 mm 단위 계산(DOM 측정 없음):** 테마가 제목·섹션 라벨·마디 줄·가사 큐 높이를 mm로 정하고, `layout()`은 그 숫자만으로 쪽을 나눔. 미리보기 CSS가 같은 숫자를 CSS 변수로 받아 고정 높이로 그리므로 계산과 화면이 일치(실측 오차 0.05mm). — 순수 함수라 테스트 가능하고, PDF에서도 같은 결과.
- **쪽 넘김 규칙:** 섹션이 현재 쪽에 안 들어가면 → 새 쪽에 통째로 들어가는 경우 통째로 넘김. 한 쪽보다 긴 섹션은 줄 단위로 넘기되 라벨은 첫 줄과 붙여 둠. `---`는 강제 넘김(쪽 맨 위에서는 무시).
- **임시 표시:** Phase 3 에디터 전까지 앱은 `examples/샴푸의요정.chord`를 바로 보여줌(Vite `?raw` 가져오기).
- **Phase 6으로 미룬 것:** 반복 기호·엔딩, 별표·브레스, 지시문, 색 메모는 문서 모델에는 있으나 아직 그리지 않음. 색 메모 높이도 아직 쪽 계산에 넣지 않음.
- **폰트:** Phase 4에서 내장 전까지 맑은 고딕(시스템 폰트) 사용.

## 2026-10-04 (Phase 2 수정 — 사용자 요청)
- **마디선 입력 `,` `.`:** `,` = 일반 마디선(`|`와 같음), `.` = 마침줄. "문장처럼" 쓰기: 줄 앞 마디선과 줄 끝 `,` 생략 가능(`Bb^7, A-7, F B7*`). `|` 입력도 그대로 됨. — 한글 자판에서 `|`는 Shift가 필요해 느림.
  - 이 때문에 **특별한 기호로 시작하지 않는 모든 줄은 마디 줄**로 읽음("알 수 없는 줄" 오류 대신 코드 오류로 표시).
  - 엔딩 `1.`은 뒤에 내용이 이어질 때만 엔딩. `1.`만 있는 줄은 1도 + 마침줄.
  - 괄호 안 쉼표(`C7(b9,#11)`)는 마디선이 아님.
  - 줄 끝 `?`는 마디선 뒤 또는 공백 뒤(`C, A- ?`).
  - 예제 파일을 쉼표 형식으로 바꿈. 빈 마디는 `A7, ,`.
- **글꼴: Pretendard(가변 글꼴) 내장.** 사용자는 애플 고딕을 원했으나 Apple 글꼴은 macOS 전용 라이선스라 앱에 넣을 수 없음. Pretendard는 Apple SD Gothic Neo와 거의 같은 모양을 목표로 만든 오픈 글꼴(SIL OFL)이라 대체. npm `pretendard` 패키지에서 가져옴. (Phase 4 "폰트 내장" 중 본문 글꼴만 먼저 함.)
  - Pretendard에는 ♯ ♭가 없어 Segoe UI Symbol로 대체 표시(별도 크기·간격). 기호 전용 글꼴 내장은 Phase 4에서.
- **마디선 모양:** 줄 높이의 62%, 굵기 0.9mm로 짧고 굵게. 마침줄은 가는 선 + 굵은 선.
- **간격 축소(사용자 요청, 한 쪽에 약 20% 더):** 여백 위아래 14→10mm·좌우 14→12mm, 제목 20→15, 2쪽 제목 12→9, 섹션 간격 4→3, 섹션 라벨 8→6.5, 마디 줄 14→12, 가사 큐 5→4mm. 글자 크기도 조금씩 줄임(코드 크기는 그대로). 4줄+가사 큐 섹션 기준 한 쪽에 약 25% 더 들어감. 예제는 3쪽 → 2쪽.

## 2026-10-04 (Phase 3)
- **에디터 구성:** CodeMirror 6 개별 패키지(state, view, commands, lint, search)만 씀. `basicSetup`은 자동완성·접기 등 필요 없는 기능이 많아 제외.
- **색칠·힌트·오류는 모두 core `parse()` 결과로:** 파서가 줄마다 "이 부분이 무엇인지"(`spans`: 코드, 마디선, 섹션 등)를 함께 돌려주고, 에디터는 그것으로 색을 칠함. 별도 문법 정의를 두지 않아 파서와 색칠이 어긋나지 않음.
- **회색 힌트:** 코드 뒤에 정규형을 표시. `#`↔♯, `b`↔♭, 대소문자만 다를 때(`f#7`, `E7b9`)는 표시 안 함. 툴바 "힌트"로 끄고 켬.
- **오류 표시:** 빨간 물결 밑줄 + 줄 번호 옆 점, 마우스를 올리면 이유. 툴바 오른쪽에 오류·경고 수.
- **미리보기:** 입력 후 80ms 뒤 다시 그림. 창 폭에 맞게 축소(확대는 안 함).
- **파일:** 열기/저장은 메인 프로세스(`src/main/files.ts`)에서만. UTF-8로 저장, 열 때 BOM 제거. 새 파일은 빈 상태에서 시작하고 입력 칸에 예시를 흐리게 보여줌.
- **미저장 표시:** "바뀜" 여부는 마지막 저장 내용과 비교(되돌리기로 원래대로 돌아오면 저장 안 해도 됨). 창 제목 앞에 `*`. 새 파일·열기·창 닫기 때 "저장 / 저장 안 함 / 취소" 질문.
- **단축키:** Ctrl+N 새 파일, Ctrl+O 열기, Ctrl+S 저장, Ctrl+Shift+S 다른 이름으로 저장.

## 2026-10-04 (안드로이드 대비 구조, 이름 변경 — 사용자 결정)
- **앱 이름: Chordash.** 이전 가칭 chordpad를 전부 바꿈(앱 표시 이름·창 제목·설치 파일 이름·앱 ID `com.chordash.app`·패키지 이름·문서·프로젝트 폴더 `C:\src\chordash`). 위의 지난 기록에 나오는 "chordpad"는 당시 이름 그대로 둠. 악보 파일 확장자 `.chord`는 앱 이름과 무관해 유지.
- **안드로이드(Capacitor) 대비 원칙:** 나중에 Capacitor로 안드로이드 버전을 냄. 지금 기능은 데스크톱 기준으로 만들되:
  1. 파일 입출력, PDF 출력, 키 보관, 외부 API 호출은 `platform` 인터페이스(`src/platform/types.ts`) 뒤로 숨기고, Electron 구현은 그 인터페이스의 한 구현체(`src/platform/electron/`)로 만든다.
  2. renderer는 Electron이나 Node API를 직접 부르지 않고 `platform` 인터페이스만 쓴다.
  3. 화면 배치는 좁은 화면에서 에디터·미리보기 탭 전환이 되게 반응형으로 만든다.
- **적용하며 고친 것:**
  - renderer가 직접 쓰던 `window.api`(Electron 통로) → `platform` 인터페이스로 교체. 통로(`window.chordashBridge`)는 Electron 구현체만 사용.
  - 파일 경로(`string`) → `FileRef { id, name }`. 데스크톱은 id = 경로, 안드로이드는 id = URI 예정.
  - "저장 안 하고 닫기" 확인 흐름을 renderer의 공통 코드로 옮김. 플랫폼은 "닫기 전에 알려주기"(`onBeforeClose`)만 제공. 창 제목 `*` 표시는 `setDocumentState`로 플랫폼이 알아서(데스크톱은 창 제목, 모바일은 생략 가능).
  - 쓰지 않던 `window.electron`(Electron 통신 전체) 노출과 `@electron-toolkit/preload` 패키지 제거. 렌더러 샌드박스 켬(`sandbox: true`).
  - 좁은 화면(760px 이하)에서 "입력 / 악보" 탭.
  - **ESLint로 경계 강제:** `src/renderer`, `src/core`에서 `electron`·Node 모듈·`platform/electron` 직접 가져오기와 `window.chordashBridge` 사용을 금지. `src/core`는 `platform`도 금지.

## 2026-10-05 (Phase 6 문법 추가 — 사용자 결정)
- **반복 기호 `.:` `:.`:** `.`이 마침줄이므로 모양대로 `.:`(마디선 → 점) = 반복 시작(`||:`과 같음), `:.`(점 → 마디선) = 반복 끝(`:||`과 같음). 쉼표·`|`와 섞어 쓸 수 있음. 홀로 쓴 `.`는 계속 마침줄.
- **엔딩 `1end` `2end` `end1` `end2`:** `1.` `2.`와 같은 뜻, 대소문자 무관. 줄 맨 앞(파트 표시 다음)에 씀. `1.:`는 엔딩이 아니라 1도 + 반복 시작.

## 2026-10-05 (Phase 6 — 반복기호와 주석 그리기)
사용자 결정(추천안 채택):
- **브레이크 표시:** 밴드 전체가 쉬는 마디는 `nc` → **N.C.**(리드시트 표준). 마디 위에 글자를 쓰려면 마디 안에 `"Break"`(Stop, Fill, rit. 등 두루). 킥은 기존 `*`(악센트), 짧은 숨은 기존 `'`(V).

구현:
- **문법:** `nc`는 코드 대신 쓰는 "코드 없음"(조옮김·힌트 대상 아님). 마디 안 따옴표 글자는 그 마디의 글자 목록(쉼표·점을 넣어도 마디선으로 읽지 않음, 닫는 따옴표 없으면 오류). 단독 지시문 줄은 "줄 전체가 따옴표 글자 하나"일 때만 — 따옴표로 시작하는 마디 줄(`"Break" nc, F7`)과 구분.
- **줄 높이(쪽 나누기):** 마디 줄 = 색 메모 줄 수 × 4.5mm + (엔딩이나 마디 위 글자가 있으면 5mm) + 마디 12mm + (가사 큐 4mm). 단독 지시문 줄 6mm. 예제 곡은 Outro의 색 메모 높이가 더해져 2쪽 → 3쪽.
- **그리기:** 도돌이 시작 = 굵은선+가는선+점, 끝 = 점+가는선+굵은선(마침줄과 같은 굵기 조합). 엔딩은 마디 줄 위의 꺾쇠 괄호와 "1." 글자(줄 전체 폭). 악센트 >는 코드 위, 브레스 V는 코드 왼쪽 위. `?` 코드는 주황 점선 밑줄. 색 메모는 줄 위에 해당 색 글자(teal·red·blue·green·orange·purple·gray). 섹션 라벨의 지시문은 라벨 옆 기울임 글자, 단독 지시문은 한 줄.
- **입력 칸:** 칸이 닫히면 `nc` → N.C., 마디선은 | ‖ ‖: :‖ 기호로 표시.

- 예제 곡을 도수로 → 음이름으로 바꾸면 원래 글과 똑같은지 테스트로 고정.

## 2026-10-07 (Phase 10 — 셋리스트 PDF)
- **`.setlist` 파일:** UTF-8 텍스트. 첫 줄 `// Chordash 셋리스트`, `title: 공연 이름`, 그다음 한 줄에 곡 파일 하나(`songs/곡.chord | key: G`). 곡 경로는 셋리스트 파일 기준 상대 경로(`/`로 씀) — 폴더째 옮겨도 그대로 열림. 다른 드라이브면 절대 경로. `|`는 Windows 파일 이름에 쓸 수 없는 글자라 구분자로 안전. 사람이 메모장으로 고쳐도 읽힘.
- **곡은 매번 파일에서 새로 읽음:** 셋리스트에는 곡 내용을 복사하지 않음. 곡을 고쳐 저장하면 다음 PDF에 바로 반영. 없어진 파일은 목록에 빨간 줄로 표시하고 PDF에서 뺌(만들기 전에 알림).
- **곡별 키:** 목록에서 곡마다 출력 키 입력(비우면 곡에 적힌 키). 곡 파일은 바꾸지 않고 PDF에서만 조옮김(`transposeDocument`, 섹션 키도 같은 간격만큼). 곡에 `key:`가 없으면 조옮김 못 한다고 알림.
- **PDF 구성:** 목차(곡 순서·출력 키·"원래 키"·시작 쪽) → 곡마다 새 쪽 → 모든 쪽 아래 가운데 쪽 번호. 목차는 한 쪽에 24곡까지, 넘으면 목차 쪽이 늘고 곡 시작 쪽이 그만큼 밀림(core `planSetlist`). 곡 안의 쪽 제목("제목 2")은 곡 단독 PDF와 같음.
- **오류·`?` 확인:** 곡마다 오류·확인 필요(?) 개수를 모아 한 번에 묻고 PDF를 만듦.
- **화면:** 툴바 "셋리스트" 버튼 → 셋리스트 창(곡 추가·지금 곡 넣기·▲▼·✕·열기·저장·다른 이름으로·PDF 만들기). 창을 닫아도 앱이 켜져 있는 동안 목록은 남음. "지금 곡 넣기"는 저장된 파일 기준(저장 안 한 내용은 안 들어간다고 안내).
- **플랫폼 인터페이스:** `pickSongs`, `readSong`, `openSetlist`, `saveSetlist` 추가. 상대 경로 계산은 저장 위치가 정해진 뒤 메인 프로세스가 함(안드로이드는 URI 기준으로 같은 인터페이스 구현).
- **대화상자 폭 고침:** 좁은 화면에서 모든 대화상자가 화면보다 8px 넓던 것(여백이 폭 밖에 더해짐)을 `box-sizing: border-box`로 고침.
- **자동 점검용 환경 변수:** `CHORDASH_TEST_SONG_PATHS`(`;`로 구분한 곡 파일들), `CHORDASH_TEST_SETLIST_PATH`(셋리스트 열기/새로 저장 위치). 평소에는 쓰지 않음.
- **버튼 이름 변경(사용자 요청):** [도수로] [음이름으로] → **[123] [CDE]**. 바뀔 모양을 그대로 보여 줘서 더 직관적. 마우스를 올리면 설명이 뜸.

- **가사·위쪽 글자 문법 `_` / `^`:** 따옴표는 열고 닫기가 번거롭고 지시문·마디 위 글자와 헷갈려서, 줄 앞 방향 기호로. `_`(밑줄)=마디 줄 아래(가사), `^`(위 꺾쇠)=마디 줄 위. 쉼표·`|`로 나누면 마디마다, 코드 줄 끝에 이어 써도 됨. `>`보다 `_`를 고른 이유: 위아래 대칭(`^`/`_`), 악센트 표시(악보의 `>`)와 안 겹침, 휴대폰 기호 첫 화면. `>`는 계속 예약. 작은따옴표는 브레스 마크(`'`)·영어 아포스트로피와 부딪혀 제외.

- **휴대폰 전용 코드 키보드:** 터치 화면(`pointer: coarse`)에서 입력 칸을 누르면 휴대폰 키보드 대신 앱이 그린 키(C~B / ♭ ♯ m maj ø dim aug / 7 9 6 11 13 sus / / 브레스 악센트 ( ) : N.C. 가사_ / 가 ⌫ 띄움 ,마디 .끝 ⏎). 맨 위 추천 줄은 곡 키의 7화음(메이저: Imaj7 ii7 iii7 IVmaj7 V7 vi7 viiø, 마이너: i7 iiø ♭IIImaj7 iv7 V7 ♭VImaj7 ♭VII7 — 재즈 차트처럼 V7, core `diatonicChords`). 가사·위쪽 글자·제목·키·섹션·메모·주석 줄과 줄 끝 `_`/`^` 뒤에서는 자동으로 휴대폰 키보드, "가" 키는 그 줄에서만 휴대폰 키보드. 툴바 "코드 키보드" 칩(터치 화면에만)으로 끄고 켬(기기에 기억). 구현: 입력 칸에 `inputmode="none"`(편집기 바깥일 때도 none으로 두어 탭할 때 휴대폰 키보드가 먼저 뜨지 않게) + 필요할 때 포커스를 다시 줘서 키보드를 바꿈. ⌫는 누르고 있으면 계속 지움. 에뮬레이터에서 휴대폰 키보드가 안 뜨는 것(`mInputShown=false`)과 가사 키로 전환되는 것 확인.
- **(버그) 인쇄 시 마침줄·도돌이표가 사라짐 — 사용자 환경 ezPDF:** 마디선을 그라데이션(PDF 안에서는 셰이딩)으로 그려서, ezPDF 같은 뷰어·프린터나 "배경 그래픽"을 끈 브라우저 인쇄에서 빠짐. 모든 마디선·도돌이 점을 단색 테두리(border)로 다시 그리고 `print-color-adjust: exact` 추가. 같은 시험 PDF가 37KB → 18KB(셰이딩이 사라짐), 모양은 같음.
- **악보 모양 변환을 칸 단위로 되돌림:** 1.1의 줄 단위 변환은 고칠 코드를 찾아가기 어려움(줄 전체가 글자로 바뀌며 위치가 출렁임, 사용자 피드백). Phase 4.5 방식(커서가 닿은 칸만 글자, 쉼표로 닫으면 바로 악보 모양)으로. 줄 끝에 `_ 가사`를 이어 쓸 때는 마지막 칸이 닫힌 것으로 봄.
- 버전 1.2.0.

## 2026-10-08 (1.3 패치)
사용자 결정:
- **구글 드라이브 — 웹 먼저:** chordash.app에서 구글 로그인 → 내 드라이브의 `Chordash` 폴더. 곡 열기·저장 창 위에 "이 브라우저 | 구글 드라이브" 전환(마지막에 고른 곳을 기억, 새 저장도 그곳으로). 구글 로그인은 Google Identity Services의 토큰 방식(팝업) — 서버·클라이언트 보안 비밀 없이 클라이언트 ID만 씀(공개 값이라 코드에 넣음). 권한은 `drive.file`(앱이 만든 파일만). 토큰은 메모리에만(약 1시간, 끝나면 다시 로그인 팝업). 첫 클릭에 팝업이 막히지 않도록, 드라이브 칸이 보이면 구글 로그인 스크립트를 미리 불러 둠. 페이지 보안 정책(CSP)에 `accounts.google.com/gsi`(스크립트·스타일·프레임)와 `www.googleapis.com`(데이터) 허용. 데스크톱·안드로이드는 다음에.
- 사용자가 채팅에 클라이언트 **보안 비밀**도 보냈으나 저장하지 않음(웹에는 필요 없고, 공개 저장소에 비밀값을 두지 않는 규칙). 채팅에 나왔으므로 Google Cloud에서 재설정을 권함.
- **보관함 구조:** 장소(`LibraryStore`: 이 브라우저/휴대폰 폴더, 구글 드라이브)를 여럿 둘 수 있게 `platform/library`를 바꿈. 파일 식별값은 `장소:파일이름`. 셋리스트는 같은 장소의 곡을 이름으로, 다른 장소·다른 곳의 곡은 내용을 담아 저장.
- **그림 중심 도움말:** 키캡(기호 + 작은 이름) → 화살표 → 실제 악보 그림 카드. 그림은 앱의 악보 그리기 코드로 그때그때 그림(`snippetHtml`). 같은 뜻의 다른 표기는 카드 아래 작게 "이것도 됨". 덜 쓰는 것(`?`, `//`, `---`)은 "더 알아보기"로. 키 이름은 `keyNames.ts` 하나로 도움말·휴대폰 코드 키보드가 함께 씀(키보드도 기호 + 작은 이름 모양으로).
- **첫 실행 둘러보기:** 4장(환영 → 마디는 쉼표로 → 가사는 _ → 악보·PDF·도움말). 처음 한 번, 이후 ⋯ → 둘러보기.
- **제목·키는 입력칸으로만:** 편집 화면에서 머리말 `title:`/`key:` 줄을 숨김(커서도 건너뜀, 줄 번호도 숨긴 줄을 빼고 셈). 파일에는 그대로 저장 — 예전 파일·다른 버전과 호환. 자동완성에서 `title:` `key:` `lyric:` 제안 없앰(섹션 키 변경 `[B] key:`는 그대로). 빈 화면 예시·예제 곡 맨 위 설명 주석 정리.
- **코드 풀이를 코드 위에 작게:** 옆에 끼어들던 것을 폭 없는 자리표 위에 띄워 줄이 움직이지 않게.
- **곡 이름 표시:** 저장 전에는 제목 칸의 곡 제목. **휴대폰 문제 표시:** 곡 이름 옆 작은 빨간(오류)·주황(경고) 숫자.
- 버전 1.3.0.

## 2026-10-09 (1.4 패치)
사용자 결정:
- **구글 앱 게시와 정책 페이지:** "테스트 중" 상태라 본인도 로그인이 막혔음(403 access_denied) → 앱 게시. 브랜딩 확인용으로 `chordash.app/privacy`(개인정보처리방침, 한·영, Google API 사용자 데이터 정책의 Limited Use 문구 포함)와 `/terms`(서비스 약관)를 정적 페이지로(`src/renderer/public`). 심사가 홈페이지에서 방침 링크를 찾으므로 웹 화면 오른쪽 아래에 작은 링크(`features.legalLinks`, 웹만, 좁은 화면에서는 숨기고 정보 창에).
- **저장 버튼은 PDF 옆:** 자주 누르는 두 버튼을 한곳에. 휴대폰에서도 보임(아이콘만).
- **로그인은 오른쪽 끝, 구글 서비스처럼:** [로그인] → 프로필 사진(없으면 이름 첫 글자). 메뉴에 이름·이메일·새 곡 저장 위치·로그아웃. 프로필은 추가 권한 없이 Drive의 `about`(drive.file로 됨)에서 받음 — 구글 설정을 바꾸지 않아도 됨. 사진 주소 때문에 CSP `img-src`에 `*.googleusercontent.com`. 마지막 프로필은 이 기기에 기억해서(`chordash.driveProfile`) 로그인이 끝난 뒤에도 흐린 사진으로 보이고, 누르면 같은 계정으로 바로 다시 연결(`login_hint`). 토큰은 여전히 메모리에만. 다른 계정으로 바뀌면 기억한 드라이브 폴더 id를 지움. 로그아웃은 토큰을 구글에 돌려줌(revoke). 렌더러는 `Platform.account`(선택 항목, 웹만)로만 다룸.
- **열기 = 가져오기:** `Platform.openFile()`이 `OpenResult`(곡 / 바꿀 파일 / 붙여넣기)를 돌려줌, `importFile`은 없앰. 사진·PDF인지 텍스트인지는 이름과 파일 첫 바이트로(`isChartFile`). 웹·안드로이드는 열기 창(보관함 목록)에 "다른 파일…" "글 붙여넣기…"; 데스크톱은 시스템 열기 창(모든 악보 형식 필터)이라 붙여넣기는 ⋯ 메뉴에(`features.libraryDialog`, `data-unless`). 다른 형식을 열면 예전 가져오기와 같이 저장 안 된 새 곡 + 원본 보기.
- **입력법 = 한 장짜리 키 표:** 그림 카드·첫 실행 둘러보기를 없애고 키 ↔ 뜻 1:1 표(마디 / 코드 / 글자 / 줄) + "이렇게 치면" 예시 한 줄(앱의 악보 그리기로). 다른 표기("이것도 됨")는 "보통 표기도 그대로 돼요" 한 줄로. 처음 켤 때 한 번 자동으로.
- 버전 1.4.0.
